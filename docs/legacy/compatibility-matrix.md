# Compatibility Matrix

Behavior-by-behavior: what Studio keeps compatible, what it deliberately breaks, and why.

**Columns:**

- **Legacy behavior** — what the legacy render module does.
- **Studio behavior** — what Studio does.
- **Compat requirement** — must an external party (Render Worker, Telegram users,
  operators) still get the outcome they depend on?
- **Break?** — is this an intentional breaking change?
- **Reason**

---

## Worker REST API

| Legacy behavior                                                                                                              | Studio behavior                                                                                                            | Compat requirement                          | Break?                                                                                         | Reason                                                         |
| ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Endpoints unauthenticated                                                                                                    | Service credential required on every endpoint                                                                              | Worker must add a credential header         | **YES (intentional)**                                                                          | K1 — security. The one unavoidable Worker change.              |
| Base path `/jobs/...`, `/files`, no version                                                                                  | `/api/worker/v1/jobs/...`, `/api/worker/v1/files`                                                                          | Worker base-URL config update               | **YES (intentional)**                                                                          | Versioned external contract (ADR-0004).                        |
| `GET /jobs/fetch`, 404 when empty                                                                                            | `POST /jobs/next`, `204` when empty (a `GET` alias + `404` for empty is an OPEN DECISION for smoother compat)              | Worker "get next job" call                  | Partial — **prefer** keeping a compatible response for the empty case                          | Side-effecting GET is wrong (K21); but minimize Worker churn.  |
| `fetch` response fields: `id, output, title, composition, template, assets[]` with asset `{composition,layer,type,src,text}` | **Same field names**, values sourced from the Job snapshot; new fields may be added                                        | Worker parses these fields                  | **NO**                                                                                         | Deliberate compatibility — keep the Worker's parser unchanged. |
| `fetch` non-atomic (double-claim possible)                                                                                   | Atomic claim                                                                                                               | Worker expects one job per call             | **NO** (improvement, invisible to Worker)                                                      | K3.                                                            |
| `PATCH /jobs/:id/state` accepts any integer 0–9                                                                              | Accepts legacy integers **and** Studio state names; maps + validates against the state machine; invalid transition → `409` | Worker sends numeric states (2/3/4 etc.)    | **NO** for valid sequences; a Worker sending nonsense now gets `409` instead of silent success | K14 — correctness.                                             |
| `PATCH /jobs/:id/progress` `{progress}` unvalidated                                                                          | Same path, `{progress: 0..100}` validated                                                                                  | Worker reports progress                     | **NO** for valid values                                                                        | Range check.                                                   |
| `PATCH /jobs/:id/duration` `{duration}` unvalidated                                                                          | Same path, `{durationSeconds}` validated ≥ 0 (field rename is an OPEN DECISION — keep `duration` for compat?)              | Worker reports duration                     | Minor — keep `duration` key if the Worker sends it                                             | Avoid needless break.                                          |
| `POST /jobs/:id/upload` multipart `.mp4`, returns `200`, then fire-and-forget delivery                                       | `POST /jobs/:id/result` multipart, validated by content type + size, returns `202`, durable delivery                       | Worker uploads the file and expects success | Partial — success is still signalled; status code differs (`200`→`202`); path differs          | ADR-0016, K10. Confirm the Worker doesn't hard-check `200`.    |
| `POST /files` authenticated as a **user** (`FILE_ADD`)                                                                       | `POST /api/worker/v1/files` authenticated as the **Worker**                                                                | Worker uploads input files                  | **YES (intentional)**                                                                          | Worker is a machine principal, not a user (ADR-0004).          |
| No idempotency on any endpoint                                                                                               | Progress/state/duration idempotent; result upload safe to retry                                                            | Worker retries on network failure           | **NO** (improvement)                                                                           | Robustness.                                                    |

## Job states & lifecycle

**Implemented, Phase 6.** See [../domain/jobs.md](../domain/jobs.md), ADR-0029.

| Legacy behavior                                                          | Studio behavior                                                                                                                     | Compat requirement                                      | Break?                                                | Reason / classification                                       |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------- |
| 10 numeric states (2/3/6 rarely/never set by backend)                    | 8 named canonical states; legacy ints will be mapped at the future Worker API boundary (Phase 7)                                    | Worker + operators understand job progress              | **NO** (mapping preserves meaning)                    | **Intentionally changed / improved.** ADR-0013, ADR-0029.     |
| `Downloading`/`Started`/`InProgress` as distinct worker substates        | Collapsed to `RENDERING` internally; the future Worker API will still accept 2/3/4                                                  | Worker sends these                                      | **NO** at the API; internal UI shows less granularity | **Simplified.** OPEN DECISION to keep substates (unaffected). |
| Terminal states: `Uploaded`, `Cancel`; `Rendered`+ blocks retry/cancel   | `UPLOADED`, `ERROR`, `CANCELED` terminal; cancel allowed only from `QUEUED`/`CLAIMED`/`RENDERING` — **enforced**, not just intended | Operators expect the same "can't cancel a finished job" | **NO**                                                | **Improved** (now actually enforced, by the state machine).   |
| `changeStateJob` accepted any integer, no validation                     | Every transition validated against a fixed graph (`isValidTransition`); rejected otherwise                                          | Worker/operators expect consistent state                | **YES (intentional)** — closes a correctness gap      | **Improved.** ADR-0013, ADR-0029.                             |
| `fetch` non-atomic (`findOne` → `save`) — two Workers could double-claim | Atomic claim (`SELECT ... FOR UPDATE SKIP LOCKED`) — manually verified race-free                                                    | Worker claims exactly one job per call                  | **NO** (invisible improvement)                        | **Improved.** ADR-0029.                                       |
| Job deleted on retry                                                     | Job **never** deleted                                                                                                               | Operators/reports rely on job history                   | **NO break for consumers** — pure improvement         | **Improved.** ADR-0005, ADR-0031.                             |

## Retry

**Implemented, Phase 6.** See [../domain/jobs.md](../domain/jobs.md), ADR-0031.

| Legacy behavior                                                 | Studio behavior                                                                                              | Compat requirement                                             | Break?                                                               | Reason / classification                                                       |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Retry deletes original, creates replacement (and could lose it) | Retry creates a **new** Job, original kept untouched, linked via `retryOfJobId`                              | Operator can retry a failed job                                | **NO break in the user-facing action**; the data model differs       | **Improved / bug fix.** ADR-0005, ADR-0031.                                   |
| Quota checked **after** delete — a failed check meant data loss | Cap checked **before** any write, inside the same transaction as the insert                                  | Operator gets a clear "cap reached" and keeps their job        | **NO break** — strictly better                                       | **Improved.**                                                                 |
| Eligibility: non-terminal (almost any state) + < 3 days         | Eligibility: `ERROR` or `CANCELED` only + `JOB_RETRY_WINDOW_DAYS` (default 3, configurable)                  | Operator retries recent failures                               | **Intentionally narrower** — retrying an active job never made sense | **Intentionally changed.** Resolves OD-02 — see [jobs.md](../domain/jobs.md). |
| `retriedCount` increments; `_retriedBy` set                     | `attemptNumber` increments; `retriedByUserId`/`retryReason` recorded; full lineage chain                     | Operator sees "this was retried"                               | **NO** (richer)                                                      | **Improved.**                                                                 |
| Retry re-copied `assets` from the deleted original's live state | Retry copies the original's immutable `snapshot`/`JobAsset` rows verbatim, never re-resolving Template/Files | Operator's retry renders what the original was meant to render | **NO break** — strictly safer                                        | **Improved (historical integrity).** ADR-0031.                                |
| No audit entry                                                  | Not yet audited (no `AuditEntry` model exists — OD-23 unaffected)                                            | —                                                              | —                                                                    | **Deferred**, not yet Preserved/Improved.                                     |

## Cancel

**Implemented, Phase 6** (single-Job cancel only — no bulk endpoint yet).

| Legacy behavior                                                         | Studio behavior                                                                            | Compat requirement                         | Break?                  | Reason / classification                                                                |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------ | ----------------------- | -------------------------------------------------------------------------------------- |
| Bulk cancel; terminal jobs silently skipped; returns the cancelled ones | Single-Job `cancelJob`, idempotent; same eligibility rule (bulk cancel not built yet)      | Operator cancels a job                     | Partial — bulk deferred | **Deferred** (bulk), **Preserved** (single-job eligibility rule).                      |
| Cancel resets `progress`/`duration` to 0                                | Keeps `progress`/`durationSeconds`/the whole timeline exactly as they were at cancellation | Operator sees a cancelled job              | Minor display change    | **Improved.** Resolves OD-26 — historical integrity favors keeping data.               |
| Telegram "Cancel All" cancels **every** job system-wide                 | No Telegram surface yet; the web UI's `cancelJob` is scoped to the actor's own Department  | Operators cancel _their department's_ jobs | **YES (intentional)**   | **Improved / security fix.** K8 — this was a serious authorization bug, not a feature. |

## Job creation & worker fetch

**Implemented, Phase 6** (creation); the fetch/claim application service is implemented
but not yet exposed over REST (Phase 7).

| Legacy behavior                                                                 | Studio behavior                                                                                         | Compat requirement                                    | Break?                             | Reason / classification                                                                            |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------- |
| No department/ownership scoping — any user with access could create/see any job | Every Job's Department is derived from its Template; USER/MANAGER act only within it, ADMIN system-wide | Operators shouldn't see/create in other departments   | **YES (intentional)**              | **Improved / security fix.** ADR-0011, closes a real isolation gap.                                |
| Template's `disabled` state was not checked by `addJob`                         | Job creation rejects a `DISABLED` or soft-deleted Template                                              | Operators can't create jobs from an unusable template | **YES (intentional)** — closes K20 | **Improved.**                                                                                      |
| A missing required asset threw a generic "not found"                            | A missing/invalid/wrong-kind/cross-department asset throws a specific, safe `business_rule` error       | Operator gets a clear reason for rejection            | **NO break** (clearer message)     | **Improved.**                                                                                      |
| `fetch`: `GET /jobs/fetch`, non-atomic, unauthenticated                         | `claimNextJob()` application service: atomic, global queue, FIFO — **not yet exposed over REST**        | Worker claims the next job                            | N/A yet                            | **Deferred** (REST exposure) — see [../integrations/worker-api.md](../integrations/worker-api.md). |
| Upload cap: global, 3/UTC-day, race-prone                                       | Same value and scope, but concurrency-safe (Postgres advisory lock)                                     | Operator sees the same daily limit                    | **NO** (same rule, now race-free)  | **Preserved (value/scope), improved (concurrency).** ADR-0030.                                     |

## Templates

**Implemented, Phase 5.** See [../domain/templates.md](../domain/templates.md), ADR-0027.

| Legacy behavior                                                                                                  | Studio behavior                                                                                                                                                                                                                      | Compat requirement                                                                     | Break?                                                        | Reason / classification                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| No delete                                                                                                        | Soft delete; row kept forever, never resolvable in normal lists again                                                                                                                                                                | Historical jobs resolve their template                                                 | **NO break** (new capability)                                 | **Improved.** ADR-0006.                                                                                                                 |
| No department/workspace scoping — `FILE_VIEW`-style global visibility                                            | Every Template belongs to one Department; USER/MANAGER see/act only within it, ADMIN system-wide                                                                                                                                     | Operators shouldn't see other departments' templates                                   | **YES (intentional)**                                         | **Improved / security fix.** ADR-0011, closes the "no access filters" defect in [../legacy/known-issues.md](../legacy/known-issues.md). |
| `disabled` honored only by the Telegram picker; GraphQL `addJob` could still use a disabled template             | `status: ACTIVE\|DISABLED` and `deletedAt` are real, queryable fields any future Job-creation path must check itself — not yet enforceable end-to-end since no Job feature exists                                                    | Operators can't create jobs from a disabled/deleted template, from **any** entry point | **YES (intentional)**, once Jobs land — closes K20            | **Improved (design in place; enforcement point doesn't exist yet).** See "Template / Job contract" in domain/templates.md.              |
| `name` globally unique                                                                                           | Unique per Department among non-deleted — **implemented**, partial DB index                                                                                                                                                          | Template lookup by name                                                                | Possible break if code assumed global uniqueness              | **Intentionally changed.** ADR-0011, ADR-0027 (resolves OD-09).                                                                         |
| Full-replace edit (resend every field)                                                                           | Same shape resent on edit, but assets are diffed at the **whole-list** level (replace, not per-field patch) — simpler than legacy's Mongo overwrite, not a true field-level patch either                                             | Operators edit templates                                                               | **NO break** (equal or easier)                                | **Improved.** See "Updating Template assets" in domain/templates.md.                                                                    |
| Editing changes behavior of future jobs implicitly                                                               | Editing never touches existing jobs — enforced by construction (a future Job's own immutable snapshot, not a live Template read)                                                                                                     | Operators expect old jobs unchanged                                                    | **NO break** — improvement                                    | **Improved.** ADR-0010.                                                                                                                 |
| `TemplateAsset.type` free text (`data`/`image`/`audio`/`video`; `script` injected server-side)                   | Validated `TemplateAssetKind` enum (`DATA`/`IMAGE`/`AUDIO`/`VIDEO`); no author-visible `script` kind                                                                                                                                 | Template authoring                                                                     | Possible break for exotic legacy `type` values                | **Intentionally changed** (data quality). No production data to migrate yet.                                                            |
| `imageRatio` exact-float check, Telegram only                                                                    | Named target (`PORTRAIT_9_16`/`LANDSCAPE_16_9`/`SQUARE`/`ANY`) stored on the asset; **actual tolerance-based comparison against an uploaded image is not implemented yet** — no feature accepts an image against a Template slot yet | Image uploads that were being wrongly rejected now pass                                | Not yet applicable — no regression, no fix in effect yet      | **Deferred**, not yet Preserved/Improved. OD-14 (tolerance value) stays open; tracked for the Jobs phase.                               |
| `TemplateAsset` has no File reference of its own — a Job asset held its file's path as a plain, unchecked string | `TemplateAsset.defaultFileId` — optional, department-verified, deletion-protected reference to a Gallery File                                                                                                                        | Template authoring may reuse a Gallery File as a slot default                          | **New capability**, no legacy equivalent to preserve or break | **Improved.** ADR-0027 (resolves OD-11); see "File Gallery Integration" in domain/templates.md.                                         |
| No stable per-asset identifier rules beyond a free-text `name`; duplicates were possible                         | `key` is validated (restricted charset) and unique within a Template (`@@unique([templateId, key])`, checked client-side too)                                                                                                        | Template authoring; a future Job's "fill every slot" contract                          | **NO break** — stricter validation only                       | **Improved.** See "Stable asset identifiers" in domain/templates.md.                                                                    |
